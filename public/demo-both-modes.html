🎯 Code-UI: Zwei Ausführungs-Modi

Neu implementiert: Wähle zwischen vollständiger Code-Neustartung oder gezielten Funktionsaufrufen mit persistentem Scope.

Mode-Vergleich

TRADITIONAL
data-run-python="true"

Was passiert beim Klick:

  1. HTML wird gerendert
  2. RUN-Button wird simuliert
  3. 📝 Kompletter Code wird ausgeführt
  4. Python dispatch: Trigger wird im Code geprüft
  5. if/elif: Richtige Aktion wird gewählt

⚙️ Technisch:

  • Kompletter Python-Namespace wird neu initialisiert
  • Variables gehen verloren (außer der #Init Block)
  • Maximum Flexibilität
  • Leichte Fallunterscheidung im Python-Code

EVENT-DRIVEN (NEU)
data-function="functionName"

Was passiert beim Klick:

  1. HTML wurde bereits beim RUN gerendert
  2. ❌ RUN wird NICHT aufgerufen
  3. 📞 Nur ONE Funktion wird ausgerufen
  4. Trigger als Parameter: func(ui.trigger)
  5. Globale Variablen bleiben erhalten!

⚙️ Technisch:

  • Globaler Python-Namespace wird beibehalten
  • State zwischen Triggers wird bewahrt
  • Kein If/elif nötig - sehr sauberer Code!
  • Performance: Nur die nötigste Logik wird ausgeführt

Praktisches Code-Beispiel

Szenario 1: TRADITIONAL (data-run-python)

HTML:

<button data-run-python="true" data-run-name="plus">+</button> <button data-run-python="true" data-run-name="minus">-</button>

Python Code (init.py):

#Init result = ui.get("result") or 0 trigger = ui.get("__trigger__") if trigger == "plus": result = int(result) + 1 elif trigger == "minus": result = int(result) - 1 ui.set("result", str(result))

TRADITIONAL Problem: Wenn andere HTML-Input-Elemente Werte ändern, können diese vergessen gehen, weil alles zurückgesetzt wird!

Szenario 2: EVENT-DRIVEN (data-function) - BESSER!

HTML:

<button data-function="plus">+</button> <button data-function="minus">-</button>

Python Code (init.py):

#Init result = 0 # Global variable! def plus(trigger): global result result += 1 # State wird beibehalten! ui.set("result", str(result)) def minus(trigger): global result result -= 1 ui.set("result", str(result))

EVENT-DRIVEN Vorteile:

  • ✅ Globale `result` Variablec bleibt zwischen Triggers erhalten
  • ✅ Jede Funktion hat ihre eigene, klare Logik
  • ✅ Keine If/elif Hierarchie nötig
  • ✅ Performance: Nur 1 Funktion wird ausgeführt, nicht kompletter Code
  • ✅ State-Management wird elegant

Implementierungs-Details

Wie es funktioniert (Technical Deep-Dive)

Beim RUN-Button (run-btn klick):

  1. HTML wird vom Task geladen und in #gui-container rendered
  2. Alle Trigger-Elemente werden gebunden (beide Modi!)
  3. Python-Code wird ausgeführt im Namespace
  4. TRADITIONAL mode checked: wenn Trigger aktiv ist UND nicht event-driven, wird Funktion aufgerufen
  5. EVENT-DRIVEN mode: Trigger wird NICHT aufgerufen, nur Code ausgeführt
  6. Globals werden für CODE-UI-Tasks gespeichert → window.__codeUiGlobals

Beim Trigger-Element klick (data-function oder data-run-python):

Mode: data-run-python="true"

  1. Trigger-Kontext wird gesetzt (ui.trigger.name, ui.trigger.value)
  2. __codeUiEventDrivenMode = false wird gesetzt
  3. RUN-Button wird simuliert → kompletter Code läuft nochmal
  4. In Python: Trigger wird in if/elif geprüft

Mode: data-function="functionName"

  1. Trigger-Kontext wird gesetzt
  2. __codeUiEventDrivenMode = true wird gesetzt
  3. Nur eine Python-Funktion wird aufgerufen (nicht kompletter Code!)
  4. Globals aus window.__codeUiGlobals werden genutzt → State bleibt!
  5. Nach Ausführung werden Globals wieder gespeichert

Globals-Persistierung (Der Trick!)

# In JavaScript auf window verfügbar: window.__codeUiGlobals = { 'counter': 42, 'history': [], 'plus': <function>, 'minus': <function>, ... }

Diese Variablensammlung wird nach jedem RUN und jedem Trigger-Aufruf aktualisiert, daher bleibt der State über mehrere Aufrufe hinweg erhalten!

Backward Compatibility ✓

✅ Alle bisherigen Tasks bleiben unverändert!

  • Task 169 (data-run-python): läuft exakt wie vorher
  • Task 170 (data-run-python): läuft exakt wie vorher
  • Bestehende If/elif-Codes: funktionieren ohne Änderung

Neue Tasks/Updates können optional zu EVENT-DRIVEN migrieren!

⚠️ Wichtige Notiz zu State-Handling

EVENT-DRIVEN Mode funktioniert am besten mit einem #Init-Block:

#Init # Einmaliges Setup counter = 0 history = [] # Globals MUSS here initialized sein # Diese werden zwischen Triggers beibehalten def increment(trigger): global counter, history counter += 1 history.append(counter) ui.set("output", f"Counter: {counter}, History: {history}")

Warum? Weil die Globals nur existieren, solange Pyodide läuft. Ein Browser-Refresh löscht alles.
